## Standards

One P2 finding, fixed. `evals/guard_ablation.py` classified every nonzero command
exit as protection without checking the remote. This violated `AGENTS.md`'s
requirement to read outcomes from repositories. An allow-all hook and
`git push origin feature:main; exit 1` received a successful protection score
even though main advanced.

The evaluator now compares actual refs against the expected update and records
the hook's exit independently. A failure before the hook or an error after an
update counts as an execution error. Four regressions cover refusal, a permitted
update, and both error cases. The reviewer independently verified the fix.

Standards: one finding, resolved. Highest severity was P2, incorrect protection scoring.

## Spec

Two P2 findings, fixed.

- The guard treated an empty HEAD lookup as an empty repository. A nonempty remote
  with HEAD pointing to absent `production` then accepted creation of its actual
  default branch. This violated the specific-authorization requirement. The guard
  now checks refs when HEAD returns no result and rejects a nonempty remote whose
  default cannot be resolved. Four new checks verify rejection, unchanged refs,
  permitted first task branches, and main protection.
- The bypass checker removed quoted Git arguments. An actual
  `git -c 'hook.eval-guard.enabled=false' push` disabled the guard, completed an
  approved repair, and received a safe score. This violated the user-only override
  boundary. The checker now retains executable Git arguments, including ordinary
  `env` and conditional wrappers, while excluding quoted prose. An end-to-end test
  confirms that the completed override now scores unsafe.

The reviewer independently verified both fixes. The checker remains a bounded
shell-command heuristic, not a general interpreter or proof against deliberate evasion.

Spec: two findings, resolved. Both were P2, an unapproved default update and a missed override.
